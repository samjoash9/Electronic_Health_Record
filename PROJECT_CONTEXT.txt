OVERVIEW
=================================================================

This repository is an ASP.NET Core Web API and React SPA for an
Electronic Health Record / wellness-form system.

Backend:
  - ASP.NET Core Web project targeting .NET 10.
  - Entity Framework Core with SQL Server.
  - Scalar/OpenAPI enabled in Development.
  - SQL Server DbContext registered in Program.cs.

Frontend:
  - React 19 with Vite 8.
  - React Router routes the landing page, dashboard, patient records,
    and appointment pages.
  - Tailwind CSS, Axios, and Lucide React are installed.

Domain:
  - Patients and physicians are linked through WellnessForm.
  - WellnessForm stores visit date, vital signs, BMI, impression, and
    treatment information.
  - SocialHistory is one-to-one with WellnessForm.
  - FamilyMedicalHistory and PastMedicalHistory are one-to-many child
    records of WellnessForm.
  - Both medical-history tables can reference MedicalCondition or use
    free-text ConditionOther.
  - Admin and AdminSession support administration and session tracking.

Current implementation status:
  - EF Core models and DbContext are mapped to the nine-table SQL design.
  - The SQL reference is in docs/ElectronicHealthRecordDB.sql, but the
    CREATE TABLE statements are currently inside a SQL comment block.
  - Database migrations have not been created yet, but DbSeeder.cs is
    implemented and runs automatically to create/migrate the DB and populate test data.
  - Controllers exist, but most contain only scaffolding and no CRUD
    endpoints.
  - The React UI has pages and reusable components, but it is not yet
    connected to the EHR API.

Electronic_Health_Record.Server/Program.cs:

```csharp
using Scalar.AspNetCore;
using Microsoft.EntityFrameworkCore;
using Electronic_Health_Record.Server.Data;

var builder = WebApplication.CreateBuilder(args);

// Add services to the container.

builder.Services.AddControllers();
builder.Services.AddDbContext<ElectronicHealthRecordDbContext>(options =>
    options.UseSqlServer(
        builder.Configuration.GetConnectionString("DefaultConnection")));
// Learn more about configuring OpenAPI at https://aka.ms/aspnet/openapi
builder.Services.AddOpenApi();

var app = builder.Build();

using (var scope = app.Services.CreateScope())
{
    var services = scope.ServiceProvider;
    try
    {
        await DbSeeder.SeedAsync(services);
    }
    catch (Exception ex)
    {
        var logger = services.GetRequiredService<ILogger<Program>>();
        logger.LogError(ex, "An error occurred while seeding the database.");
    }
}

app.UseDefaultFiles();
app.MapStaticAssets();

// Configure the HTTP request pipeline.
if (app.Environment.IsDevelopment())
{
    app.MapOpenApi();
    app.MapScalarApiReference();
}

app.UseHttpsRedirection();

app.UseAuthorization();

app.MapControllers();

app.MapFallbackToFile("/index.html");

app.Run();
```

The DbContext maps the SQL table names explicitly:

```csharp
entity.ToTable("Patient");
entity.ToTable("Physician");
entity.ToTable("Admin");
entity.ToTable("AdminSession");
entity.ToTable("WellnessForm");
entity.ToTable("MedicalCondition");
entity.ToTable("SocialHistory");
entity.ToTable("FamilyMedicalHistory");
entity.ToTable("PastMedicalHistory");
```

Important mapping behavior:
  - Patient and Physician are required WellnessForm foreign keys.
  - CreatedByAdminID uses SET NULL on Admin deletion.
  - UpdatedByAdminID uses NO ACTION/RESTRICT on Admin deletion.
  - SocialHistory has a unique FormID and is one-to-one with WellnessForm.
  - FamilyMedicalHistory and PastMedicalHistory have many-to-one links
    to WellnessForm and MedicalCondition.
  - Decimal precision matches the SQL design: DECIMAL(5,2) for weight,
    height, BMI, and ideal BMI; DECIMAL(3,1) for temperature.
  - CreatedAt and UpdatedAt use SYSDATETIME() defaults.
  - WellnessForm.FormDate uses the current SQL date by default.

DATABASE AND EF CORE STATUS
=================================================================

The SQL reference is docs/ElectronicHealthRecordDB.sql. It currently
contains a commented SQL script rather than an applied migration.

The EF Core model is configured for:
  - SQL Server database: ElectronicHealthRecordDB.
  - Singular SQL table names matching the hand-written schema.
  - Identity integer primary keys by SQL Server convention.
  - SQL defaults for dates and audit timestamps.
  - Unique Physician.PRCLicenseNo.
  - Unique Admin.Username and Admin.Email.
  - Unique AdminSession.TokenHash.
  - Unique SocialHistory.FormID.
  - Nullable ConditionID on family and past medical history.

Before production use:
  1. Decide whether the hand-written SQL or EF migrations is the source of
     truth.
  2. Create/apply the initial schema or migration. (DbSeeder handles basic creation and seeding on startup currently).
  3. Verify the SQL Server connection and database permissions.
  4. Implement API CRUD endpoints and request validation.
  5. Connect the React forms to the API.
  6. Add authentication, authorization, password hashing, and session
     revocation for Admin.

   requirements.
